# 제안서 메일 직접 발송 연결

현재 공개 홈페이지는 기존 메일 초안 방식을 사용합니다. `config.js`의 `directMailEnabled`가 `false`인 동안 새로운 발송 코드는 방문자에게 보이지 않습니다.

연결 후에는 로그인한 회원이 작성한 제안서를 HTML 문서로 만들고, 화면에서 선택한 파일과 함께 `435parkrio@gmail.com` 계정에서 `js-parkrio@naver.com`으로 보냅니다. 메일 내용에는 제출일이 자동 기재됩니다. **홈페이지의 제출 성공 표시가 관리규약상 공식 접수·상정을 뜻하지는 않습니다.**

1. `435parkrio@gmail.com`으로 Google Apps Script에 로그인합니다. `Code.gs` 내용을 새 프로젝트에 넣습니다.
2. 프로젝트의 스크립트 속성에 긴 무작위 문자열을 `MAIL_GATEWAY_TOKEN`으로 저장합니다. 저장소나 홈페이지 파일에 적지 않습니다.
3. Google 계정에서 이 스크립트의 메일 발송 권한을 직접 허용합니다. 웹 앱은 **실행 사용자: 나**, **접근 권한: 모든 사용자**로 배포합니다. 실제 받는 사람은 코드에서 `js-parkrio@naver.com`으로 고정되어 있고, 비밀 토큰이 없는 요청은 거절합니다.
4. Supabase Edge Function 비밀 설정에 `GOOGLE_MAIL_WEBAPP_URL`(웹 앱의 `/exec` 주소)과 `GOOGLE_MAIL_TOKEN`(2번과 같은 문자열)을 저장합니다.
5. `send-proposal` Edge Function을 배포합니다. 로그인 없이 요청하면 거절되는지, 로그인 회원의 시험 제출이 실제 받는 사람에게 도착하고 제안서 파일과 선택한 파일이 모두 첨부되는지 확인합니다.
6. 시험이 끝난 다음에만 `config.js`의 `directMailEnabled`를 `true`로 바꾸고 GitHub Pages에 배포합니다.

파일 한도는 최대 5개, 각 5MB, 전체 8MB입니다. 같은 회원은 5분 동안 다시 보낼 수 없습니다. 발송 오류가 나면 성공 표시를 하지 않습니다. 발송용 비밀번호나 비밀 토큰을 채팅·GitHub에 올리지 않습니다.
